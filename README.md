# Тренировка: слияние веток и разрешение конфликта

Учебный проект для отработки первого коммита, ветвления и разрешения
искусственного конфликта слияния в Git.

## О чём этот проект

Здесь имитируется ситуация, когда два разработчика («Алиса» и «Боб»)
изменяют одну и ту же строку файла `README.md` в разных ветках.
При слиянии Git не может автоматически выбрать нужную версию —
возникает конфликт, который разрешается вручную.

## Быстрый старт

1. Скопируйте этот репозиторий или создайте папку с файлами `README.md` и `create_conflict.sh`.
2. Выполните подготовку:

   ```bash
   git init
   git add README.md
   git commit -m "init: базовый README"
   ```

3. Запустите скрипт, который создаст две ветки с правками одной строки:

   ```bash
   bash create_conflict.sh
   ```

4. Слейте ветки и разрешите конфликт:

   ```bash
   git checkout main
   git merge feature-alice        # пройдёт без конфликта
   git merge feature-bob          # здесь возникнет конфликт
   ```

5. Откройте `README.md` и разрешите конфликт:

   ```text
   <<<<<<< HEAD
   Проект: версия Алисы (описание функционала)
   =======
   Проект: версия Боба (инструкция по установке)
   >>>>>>> feature-bob
   ```

6. Завершите слияние:

   ```bash
   git add README.md
   git commit -m "merge: разрешён конфликт между ветками feature-alice и feature-bob"
   git log --oneline --graph --all
   ```

## Варианты разрешения конфликта

| Вариант | Что сделать |
|---|---|
| Оставить версию Алисы | удалить блок Боба и маркеры |
| Оставить версию Боба | удалить блок Алисы и маркеров |
| Объединить | написать новую строку, включающую обе правки |

Рекомендуемый итог для тренировки:

```text
Проект: тренировочный проект (описание функционала + инструкция по установке)
```

## Полезные команды

- `git merge --abort` — отменить слияние и вернуться к состоянию до него.
- `git status` — увидеть, какие файлы в конфликте.
- `git diff --name-only --diff-filter=U` — только конфликтующие файлы.
